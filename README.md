# TikTok Affiliate Finder

เครื่องมือหาสินค้าสำหรับทำ **Affiliate ผ่าน Live และวิดีโอ** บน TikTok Shop **เฉพาะร้านไทย** ใช้ได้ทั้ง **ข้อมูลจำลอง** และ **ข้อมูลจริงผ่าน Apify**

## วิธีรัน

```bash
npm install
npm start          # เปิด http://localhost:3000
npm run dev        # โหมดพัฒนา รีสตาร์ตเองเมื่อแก้โค้ด
```

ค่าเริ่มต้นใช้ข้อมูลจำลอง ครั้งแรกที่รันระบบจะสร้างข้อมูลย้อนหลัง 60 วันไว้ที่ `data/store-mock.json`

## ใช้ข้อมูลจริงจาก Apify

1. สมัคร [Apify](https://apify.com) แล้วคัดลอก API token จาก **Settings → Integrations**
2. คัดลอก `.env.example` เป็น `.env` แล้วตั้งค่า
   ```
   DATA_PROVIDER=apify
   APIFY_TOKEN=apify_api_xxxxxxxx
   ```
3. แก้คีย์เวิร์ดที่จะค้นใน `config/apify.json` (แยกตามประเทศ → หมวด)
4. `npm start` ระบบจะดึงข้อมูลครั้งแรกทันที (ใช้เวลาหลายนาที) จากนั้นดึงทุกวัน 06:00 น.

ข้อมูลจริงเก็บแยกที่ `data/store-apify.json` ไม่ปนกับข้อมูลจำลอง

**สิ่งที่ควรรู้**
- actor ให้ **ยอดขายสะสม** ระบบจึงคำนวณยอดรายวันจากผลต่างของแต่ละวัน วันแรกจะยังไม่มียอดรายวัน (ตารางจะเรียงตามยอดสะสมแทน)
- ยอดสะสมที่ TikTok แสดงมักปัดเศษ เช่น "1.2K" ยอดรายวันของสินค้าที่ขายเยอะจึงหยาบ (ขยับทีละ 100)
- ข้อมูลย้อนหลังดึงไม่ได้ มีเฉพาะตั้งแต่วันที่เริ่มเก็บ ไม่มียอดวิว
- ถ้าเซิร์ฟเวอร์ปิดไปหลายวัน ยอดที่เพิ่มขึ้นทั้งหมดจะไปรวมอยู่ในวันที่กลับมาเก็บ
- **actor เริ่มต้น** คือ `bovi/tiktok-shop-scraper` เพราะให้ทั้ง**รูปสินค้า**และ**ราคา** แต่หน้า actor ไม่ได้ยืนยันว่ารองรับร้านในไทย ควรลองรันครั้งแรกแล้วเช็กว่าได้ข้อมูลจริง
- ถ้า `bovi` ใช้กับไทยไม่ได้ ให้เปลี่ยน `actorId` เป็น `tictechid/vanzi-tiktok-shop` ซึ่งรองรับไทยชัดเจน แต่**ไม่มีรูปและราคา** (ยอดขายเป็นบาทจะเป็น 0)
- ลิงก์รูปจาก TikTok อาจหมดอายุ ระบบอัปเดตรูปทุกครั้งที่เจอสินค้าในการค้นหา ถ้ารูปโหลดไม่ได้จะแสดงไอคอนหมวดแทน
- **ค่าใช้จ่าย:** `bovi` คิดราว $1.99 ต่อ 1,000 สินค้า บวกค่า residential proxy ของ Apify ค่าตั้งต้นใน `config/apify.json` คือ 16 คีย์เวิร์ด × 20 ชิ้น ≈ 320 ชิ้นต่อวัน ≈ $0.65/วัน (ไม่รวม proxy) ปรับลดได้ด้วย `maxItemsPerKeyword` หรือจำนวนคีย์เวิร์ด
- ถ้าใช้ actor ตัวอื่น ให้เพิ่มรูปแบบ input ใน `buildInput()` ของ `src/providers/apifyProvider.js`

## นำขึ้นออนไลน์ฟรีด้วย GitHub Pages

ไม่ต้องมีเซิร์ฟเวอร์ GitHub Actions จะดึงข้อมูลทุกวัน 06:00 น. (เวลาไทย) แล้ว commit ประวัติไว้ในโฟลเดอร์ `data/` จากนั้นสร้างหน้าเว็บและ deploy ขึ้น GitHub Pages ให้อัตโนมัติ

1. สร้าง repo **สาธารณะ** บน GitHub แล้ว push โปรเจกต์นี้ขึ้นไป (branch `main`)
2. ไปที่ **Settings → Pages** แล้วตั้ง **Source** เป็น **GitHub Actions**
3. ถ้าจะใช้ข้อมูลจริง ไปที่ **Settings → Secrets and variables → Actions**
   - แท็บ **Secrets** เพิ่ม `APIFY_TOKEN`
   - แท็บ **Variables** เพิ่ม `DATA_PROVIDER` = `apify`
4. ไปที่แท็บ **Actions** → **Update data & deploy** → **Run workflow** เพื่อรันครั้งแรก

เว็บจะอยู่ที่ `https://<ชื่อผู้ใช้>.github.io/<ชื่อ repo>/`

บน GitHub Pages จะไม่มีปุ่มรีเฟรช ถ้าต้องการดึงข้อมูลทันทีให้กด **Run workflow** ในแท็บ Actions แทน
ข้อควรรู้: GitHub อาจเลื่อนเวลารันตามตารางออกไปบ้างตอนที่ระบบมีคนใช้เยอะ

## ฟีเจอร์

- จัดอันดับ 4 แบบ พร้อมลูกศรบอกว่าอันดับขยับขึ้นหรือลง
  - 🔥 **ขายดี** ยอดขายสูงสุด
  - 🚀 **มาแรง** ยอดขายโตเร็วที่สุด ใช้จับกระแสก่อนคนอื่น
  - 💰 **ค่าคอมสูง** ค่าคอมรวมที่ครีเอเตอร์ได้ (ยอดขาย × ราคา × % ค่าคอม)
  - 🎯 **คู่แข่งน้อย** ยอดขายต่อครีเอเตอร์ 1 คนสูง แปลว่าขายดีแต่คนโปรโมทยังน้อย
- เลือกช่องทาง **ทุกช่องทาง / Live / วิดีโอ** เพื่อดูว่าสินค้าไหนขายดีในช่องทางที่คุณทำ
- **ป้ายช่วงกระแส** บนสินค้าทุกตัว: 🌱 เพิ่งเริ่มขึ้น · 🔥 กำลังพีค · 📉 เริ่มขาลง · 💤 ทรงตัว (ต้องมีข้อมูลอย่างน้อย 28 วัน)
- **ป้ายจุดเด่น**: ⚡ กำลังพุ่ง · 💎 ค่าคอมสูง (20%+) · 🎯 คู่แข่งน้อย · 🔴 เหมาะกับ Live · 🎬 เหมาะกับวิดีโอ
- **ประมาณรายได้ต่อคลิปและต่อไลฟ์** = ยอดขายเฉลี่ยต่อคลิป (หรือไลฟ์) × ค่าคอมต่อชิ้น
- **⭐ เก็บสินค้าที่สนใจ** พร้อมจดโน้ต กรองดูเฉพาะที่เก็บไว้ได้ และส่งออก Excel ได้ (เก็บในเบราว์เซอร์เครื่องนั้น ไม่ได้ซิงก์ข้ามเครื่อง)
- **📌 ติดตามสินค้าจากลิงก์**: วางลิงก์สินค้าหรือร้านจากปุ่มแชร์ในแอป TikTok (เช่น `https://vt.tiktok.com/...`) ระบบดึงชื่อและรูปมาแสดงเป็นการ์ดทันที ถ้าใช้ Apify จะดึงราคา ยอดขาย และลิงก์ร้านของสินค้านั้นทุกวันด้วย
  - ระบบตัดข้อมูลบัญชีที่ติดมากับลิงก์แชร์ (ชื่อผู้ใช้, user id, device id) ทิ้ง เก็บแค่ลิงก์สินค้าสะอาดไว้ที่ `data/links.json`
  - เพิ่มลิงก์บนหน้าเว็บได้เฉพาะตอนรัน `npm start` ถ้าใช้ GitHub Pages ให้เพิ่มลิงก์ในเครื่องแล้ว commit `data/links.json` ขึ้นไป
  - ลิงก์ร้าน: ดึงสินค้าในร้านได้เมื่อใช้ actor `bovi` (สูงสุด `maxItemsPerShop` ชิ้นต่อร้าน)
- **✏️ กรอกข้อมูลเอง (ฟรี)** บนการ์ดลิงก์: ราคา, "ขายแล้ว X ชิ้น" จากแอป, % ค่าคอม, ร้าน, หมวด
  - กรอก "ขายแล้ว" ซ้ำในวันถัด ๆ ไป ระบบคำนวณยอดขายรายวันจากผลต่าง (กรอกซ้ำวันเดียวกันใช้ค่าล่าสุด)
  - สินค้าที่กรอกแล้วจะเข้าไปอยู่ในตารางอันดับ กราฟ ป้าย และการคำนวณค่าคอมเหมือนสินค้าอื่น
- **วิเคราะห์ฟรีผ่านแชท Claude**: ส่งลิงก์ให้ Claude Code วิเคราะห์ แล้วบันทึกด้วย `node src/save-analysis.js <productId> <result.json>` ผลจะแสดงบนเว็บเหมือนกดปุ่ม
- ปุ่ม **เปิดใน TikTok / 📋 คัดลอกลิงก์ / 🏪 ร้านค้า** ในหน้ารายละเอียดสินค้า
- **🤖 วิเคราะห์ด้วย AI** (Claude Opus 5.5) บนการ์ดลิงก์และหน้ารายละเอียด: อ่านรูป ชื่อ และตัวเลขยอดขาย (ถ้ามี) แล้วสรุปเป็น
  คะแนนความเหมาะกับไลฟ์/คลิป พร้อมเหตุผล · กลุ่มเป้าหมาย · จุดขาย · Hook 3 วินาทีแรก · ไอเดียคอนเทนต์ · โครงไลฟ์ · ข้อควรระวัง (การกล่าวอ้าง/อย./ของปลอม) · สิ่งที่ต้องเช็กก่อนรับงาน
  - ต้องตั้ง `ANTHROPIC_API_KEY` ใน `.env` (สร้างที่ console.anthropic.com) ปุ่มจะขึ้นเฉพาะตอนรัน `npm start` ที่มี key
  - ค่าใช้จ่ายราว $0.05–0.10 ต่อการวิเคราะห์ 1 ครั้ง (แสดงจริงท้ายผลวิเคราะห์) ผลจะถูกบันทึกที่ `data/analyses.json` เปิดดูซ้ำไม่เสียเงิน กด "วิเคราะห์ใหม่" เมื่อต้องการอัปเดต
  - ผลวิเคราะห์ที่ commit ขึ้นไปจะแสดงบน GitHub Pages ด้วย (แต่กดวิเคราะห์ใหม่บน Pages ไม่ได้)
  - เป็นความเห็นของ AI จากรูปและชื่อสินค้า ควรเช็กข้อเท็จจริงก่อนตัดสินใจ
- **ค่าคอมเริ่มต้น 10%** สำหรับสินค้าที่แหล่งข้อมูลไม่มี % ค่าคอม แสดงเป็น "~10% ประมาณ" ปรับได้ด้วย `DEFAULT_COMMISSION_RATE`
- กรองตามหมวดหมู่ ค่าคอมขั้นต่ำ และช่วงเวลา (1 / 7 / 30 วัน) ค้นหาด้วยชื่อสินค้าหรือร้าน
- ส่งออกตารางตามตัวกรองปัจจุบันเป็นไฟล์ Excel (.xlsx)
- กราฟแนวโน้ม 5 อันดับแรก และกราฟรายสินค้า (กดที่แถวในตาราง)
- รูปสินค้าจริงในตารางและแกลเลอรีในหน้ารายละเอียด พร้อมลิงก์ไปหน้าสินค้าบน TikTok (เฉพาะข้อมูลจริง)
- หน้ารายละเอียดมีค่าคอมต่อชิ้น สัดส่วนยอดขาย Live/วิดีโอ จำนวนครีเอเตอร์ วิดีโอและไลฟ์ใหม่ พร้อมกราฟแยกช่องทาง

### ข้อมูลที่แต่ละแหล่งมีให้

| ข้อมูล | ข้อมูลจำลอง | Apify (ร้านไทย) |
| --- | --- | --- |
| ยอดขาย ราคา รูป ลิงก์ | ✅ (ไม่มีรูป) | ✅ |
| % ค่าคอม | ✅ | ⚠️ ใช้ค่าประมาณ 10% (ยังไม่พบ actor ที่ให้ข้อมูลจริง) |
| ยอดขายแยก Live / วิดีโอ | ✅ | ❌ |
| จำนวนครีเอเตอร์ / วิดีโอ | ✅ | ❌ actor ที่มีข้อมูลนี้รองรับแค่ US/UK |

คอลัมน์และแท็บที่แหล่งข้อมูลไม่มีให้จะถูกซ่อนอัตโนมัติ ถ้าภายหลังได้แหล่งข้อมูลที่มีฟิลด์เหล่านี้ (`commissionRate`, `liveSales`, `videoSales`, `creators`, `videos`, `lives`) หน้าเว็บจะแสดงให้เอง
- อัปเดตอัตโนมัติทุกวัน 06:00 น. (เวลาไทย) หน้าเว็บจะเช็กข้อมูลใหม่ทุก 5 นาที

## ตั้งค่า

| ตัวแปร | ค่าเริ่มต้น | ความหมาย |
| --- | --- | --- |
| `PORT` | `3000` | พอร์ตของเว็บ |
| `CRON_SCHEDULE` | `0 6 * * *` | ตารางดึงข้อมูล (รูปแบบ cron) |
| `DATA_PROVIDER` | `mock` | แหล่งข้อมูล: `mock` หรือ `apify` |
| `APIFY_TOKEN` | – | API token ของ Apify |
| `GROWTH_MIN_SALES_PER_DAY` | `5` | ยอดขั้นต่ำต่อวันที่จะติดอันดับ "มาแรง" / "คู่แข่งน้อย" |
| `ANTHROPIC_API_KEY` | – | API key สำหรับปุ่มวิเคราะห์ด้วย AI |
| `DEFAULT_COMMISSION_RATE` | `0.1` | ค่าคอมที่ใช้ประมาณเมื่อไม่มีข้อมูลจริง (0.1 = 10%, ตั้ง 0 เพื่อปิด) |
| `REFRESH_COOLDOWN_MINUTES` | `10` | ช่วงพักขั้นต่ำระหว่างการกดรีเฟรช |
| `DATA_DIR` | `data/` | โฟลเดอร์เก็บข้อมูล |

ตั้งค่าในไฟล์ `.env` ได้ (ดูตัวอย่างใน `.env.example`)

## API (เฉพาะตอนรันด้วย `npm start`)

- `GET /data.json` — ข้อมูลทั้งหมดที่หน้าเว็บใช้ (90 วันล่าสุด)
- `POST /api/refresh` — ดึงข้อมูลวันที่ยังขาดทันที
- `POST /api/links` `{ "url": "..." }` — เพิ่มสินค้า/ร้านจากลิงก์ TikTok Shop
- `PUT /api/links/:id/manual` `{ price, soldTotal, commissionPercent, shop, category }` — บันทึกข้อมูลที่กรอกเอง
- `DELETE /api/links/:id` — ลบลิงก์
- `POST /api/analyze/:id` — วิเคราะห์สินค้าด้วย AI (คืนผลเดิมถ้าเคยวิเคราะห์แล้ว ส่ง `?force=1` เพื่อวิเคราะห์ใหม่)
- `GET /healthz` — เช็กว่าเซิร์ฟเวอร์ทำงานอยู่

## เพิ่มแหล่งข้อมูลใหม่

สร้างไฟล์ใน `src/providers/` ตามรูปแบบที่อธิบายไว้ด้านบนของ `mockProvider.js` แล้วลงทะเบียนใน `PROVIDERS` ของ `src/collector.js`
